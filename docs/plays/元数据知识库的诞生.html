🎬 第六幕：问数工作流用起来
用

统计华北地区的销售总额
L
LLM · 兴奋
数据来了！ - Qdrant 告诉我："销售总额" → 搜到 `order_amount` - ES 告诉我："华北" → 搜到 `dim_region.province` 的取值 - 元数据库 MySQL 告诉我：`order_amount` 是 `decimal(10,2)` 类型，属于 `fact_order` 表 好，我写 SQL：
SELECT SUM(order_amount) AS 销售总额
FROM fact_order
JOIN dim_region ON fact_order.region_id = dim_region.region_id
WHERE dim_region.province = '华北'

谢幕总结

角色在构建阶段做的事在查询阶段做的事
元数据库（MySQL）存储结构化的表/字段/指标元数据运行时补齐主外键、指标依赖字段
Qdrant字段名/描述/别名、指标名/描述/别名 → 向量点用户问问题 → 按语义搜到相关字段和指标
ES维度字段的真实取值 → 全文索引用户问具体值（"华北"）→ 定位到所属字段
元数据知识库总指挥：配置管理、调用顺序、数据一致性离线建好、在线直接用
LLM不需要参与构建接收三路召回结果 → 理解表结构和指标口径 → 生成 SQL
产品经理提出痛点：LLM 答不上来验收：用户能问到答案
配置圈定要加工的表/字段/指标—
用户—用自然语言问数据问题
✒ LLM 很强，但不能让它现场猜数据库里有什么。构建阶段提前把数据库的"地图"（元数据）加工成 LLM 能直接用的格式（向量索引 + 全文索引 + 结构化元数据），运行时 LLM 只需查地图，不猜路。
